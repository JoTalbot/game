## Как собрать APK

SDK и JDK 17 в `/home/user/.igra-build/`.

```bash
export JAVA_HOME=/home/user/.igra-build/jdk-17
export PATH="$JAVA_HOME/bin:$PATH"
export ANDROID_SDK_ROOT=/home/user/.igra-build/android-sdk
bash tools/build-apk.sh
```

Скрипт копирует `web/` → `android/app/src/main/assets/www`, пакует aapt2+d8+apksigner.  
Keystore: `dist/debug.keystore` (gitignored). Если его нет — скрипт создаст **новый**, и человек **обязан удалить** старую ИГРУ с телефона, иначе «приложение не установлено».

## История починки экрана Android

1. 0.4.0–0.4.3: масштабирование WebView и растягивание при повторном открытии давали белое поле или сжатие.
2. 0.4.4: попытка зашить физические пиксели через JS (`applyPhysicalViewport`) и `setInitialScale(100)` сжало вьюпорт ровно в 1.5–3 раза (DPR) в левый верхний угол (384×708 на экране 576×1280).
3. **0.4.5 (настоящее решение):** убран весь костыльный JS-инжект вьюпорта из Java. WebView работает в нативном полноэкранном режиме с аппаратным ускорением (`Theme.Black.NoTitleBar.Fullscreen`, `WindowInsetsController` hide bars). HTML/CSS закреплён в `position: fixed; inset: 0; width: 100%; height: 100%`. В `engine.js` холст берет реальный `innerWidth/innerHeight` и умножает на `dpr` с матрицей `ctx.setTransform(dpr, 0, 0, dpr, 0, 0)`. В цикле кадров и на событиях resize/orientation изменения размера подхватываются на лету.

## Закон экрана (истина, добытая 0.4.22 → 0.4.33)

Симптом саги: берег занимает левую верхнюю часть экрана, справа и снизу «мягкий двойник» из старых кадров. Соотношение следует за плотностью прошивки (2/3 при dpr 1.5, 0.74 при dpr 1.35).

**Настоящий корень — в нашем коде, не в прошивке.** `renderer.js` начинал кадр с `ctx.setTransform(identity)` и заливал фон `fillRect(0,0,w,h)` — в битмапе размером `w×dpr` закрашивались только (w,h) пикселей. Видимая часть = 1/dpr битмапа; остальное — несмываемый мусор мёртвых кадров. DOM, увы, всегда рисовался честно ×dpr — отсюда «титул на весь экран», кнопки HUD за границей берега и точные касания. Метки краёв (зелёная полоса на правой кромке мира) доказали здоровье композитора: она встала в физический край экрана.

**Закон холста, навсегда:**
1. Битмап = `innerWidth × dpr`; трансформ — `setTransform(dpr,…)`; система координат мира — CSS-пиксели. НИКОГДА не сбрасывать трансформ в identity для заливки/кадра (исключение — только точечный readPixels-подобный код). Везде, где пишется `setTransform`, подставлять `game.dpr` (учитывает Quality-кепку), а не сырой `devicePixelRatio`.
2. Оболочка: позднее рождение WebView из `decorView.post()`, MATCH_PARENT, `?debug` виде́н только в диагностических сборках.
3. Диагностика делом: метки краёв в кадре (один скрин равен десяти теориям), зонд касаний — сторож, телеметрия — по `?debug`.

**Кладбище гипотез (не воскрешать):** «физический вьюпорт» meta из Java; setInitialScale/плотность; setScaleX/Y матрица view; перепин LayoutParams; GONE→VISIBLE; sw-сборка (LAYER_TYPE_SOFTWARE); willReadFrequently; manifest hardwareAccelerated=false; «обнови WebView». Ни одно не лечило, потому что лечить надо было `setTransform`.

Проверка настоящая только на телефоне человека. Превью врёт. После зелёной сессии убрать `#fit-debug` из релиза (писать только при `?debug`) — перед этим дождаться скрина с телеметрией: измеренная геометра окна G1 навсегда снимает гадания.

## Урок снапшотов этой машины (боль на раз)

Снапшот рабочего места **не поднимает** `.igra-build/` (~600 МБ > лимита): JDK, SDK и `dist/debug.keystore` умирают между сессиями. Каждая новая сессия = цех восстанавливать цепью из команд (JDK 17 Temurin → cmdline-tools → sdkmanager platform-34+build-tools) и **подпись каждый раз новая — предупреждать человека об удалении старой ИГРЫ в каждом STATUS**. `.git/config` в снапшот тоже не входит: origin с токеном пересоздавать в каждой сессии перед пушем; и `git fetch` до коммита — локальная история может отставать от origin.

## SDK и подпись на текущей машине

SDK восстановлен по рецепту выше (JDK 17 Temurin + cmdline-tools, sdkmanager ставит platforms;android-34 и build-tools;34.0.0). В скрипте javac вызывается с `-encoding UTF-8` — не убирать (комментарии по-русски). **14.08 создан новый `dist/debug.keystore`: подпись сменилась — человек обязан удалить старую ИГРУ перед установкой 0.4.23+.** Keystore снапшот не хранит: на новой машине подпись снова будет другой, предупреждай человека в STATUS.
