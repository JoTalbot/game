# RC1 — improvement backlog

Дата: 3 сентября 2026.

Этот backlog содержит улучшения, найденные на реальных прогонах RC-подготовки. Продуктовые изменения сначала фиксируются здесь, затем реализуются после подтверждения данных.

## IMP-RC1-TOUCH — adaptive touch cancellation

**Приоритет:** P1 / RC polish  
**Статус:** наблюдение подтверждено одним реальным прогоном; реализацию не включать до независимой валидации.

### Evidence

На `v2.33`, экран `427×948`, слабый профиль:

- 10 срывов;
- 3 из них — уход пальца;
- медиана ухода `128 px`;
- максимум `139 px`;
- действующий порог `126 px`.

Это указывает на пограничную зону, но не доказывает, что глобальное повышение порога улучшит игру.

### Кандидат решения

Исследовать hysteresis/grace zone:

- `0–126 px` — обычное удержание;
- `126–140 px` — временная зона допуска;
- `>140 px` — срыв при устойчивом движении наружу;
- возврат пальца внутрь grace zone не должен рвать удержание;
- явный `touchend` остаётся обычным отпусканием;
- системный `touchcancel` остаётся отдельным системным событием;
- не менять стоимость взгляда, рождение, пульс или правила мира.

### Acceptance

- deterministic probe покрывает `126–140` с возвратом;
- deterministic probe покрывает `>140` с отменой;
- explicit release не меняется;
- `touchcancel` не превращается в `slip`;
- существующие gesture probes остаются зелёными;
- на реальном слабом Android нет роста ложного удержания новых соседних узлов.

## IMP-RC1-COLOR — color discoverability

**Приоритет:** P2 / research  
**Статус:** наблюдение, без реализации.

Одна сессия дала `0` цветов. Этого недостаточно для вывода о проблеме.

### Следующее измерение

Собрать несколько независимых паспортов и сравнить:

- количество цветов;
- контекст, в котором игрок их обнаруживает;
- длительность до первого цветового взаимодействия;
- связь с природой/законами/органами;
- наличие цветового результата без внешней подсказки.

Tutorial или UI-подсказку не добавлять только ради увеличения метрики.

## Правило RC

Ни одно из этих улучшений не должно блокировать физический smoke gate само по себе. Сначала подтверждаем проблему на текущем RC1, затем меняем код и повторяем полный probe/CI + физический smoke.
