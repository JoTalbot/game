# ИГРА — backlog V4 / путь от первого акта к готовности

> Этот backlog является рабочим продолжением `docs/ROADMAP_TO_READY.md`.
> V3-030 закрыт как первый полноценный акт. Здесь фиксируются следующие продуктовые работы до Release Candidate.
>
> Правило: любое новое улучшение сначала получает `IMP-*`, затем реализуется и проверяется. Тестовые исправления без изменения продукта могут идти напрямую.

## PHASE 4 — V3.1: второй слой жизни

### V4-001. Унифицированный контур причинности
**P0 — фундамент**
**Статус:** выполняется в RC batch

Действие → событие → след → место/отношение/орган → экология → Director → будущее событие используют совместимые `causeId` и provenance.

### V4-002. Контентные archetype-пулы Director
**P0**
**Статус:** реализовано

Director получает расширяемые пулы событий по контекстам, причинам и фазам. Контент не дублирует runtime-логику и может безопасно расширяться.

### V4-003. Второй акт
**P0**
**Статус:** выполняется в RC batch

Новый акт имеет собственный конфликт и последствия, а не является набором дополнительных узлов.

### V4-004. Контент второго акта
**P0**
**Статус:** реализовано

Добавлены 10 связанных событий второго акта с физическими последствиями, памятью существ, экологическими следами, ранами и историей возвращений.

### V4-005. Повторяющиеся существа второго акта
**P1**
**Статус:** реализовано

Добавлены три устойчивые роли: Свидетель, Садовник и Хранитель-раны. У каждого есть собственная память, поведенческий режим и сохраняемая близость к игроку.

### V4-006. Исторические места второго акта
**P1**
**Статус:** выполняется в RC batch

Минимум три места меняются от возвращений и связывают несколько событий/жизней.

### V4-007. Последствия второго акта
**P1**
**Статус:** выполняется в RC batch

Результаты акта меняют минимум два слоя: органы, отношения, места, экологию или законы.

### V4-008. Контрастные маршруты
**P1**
**Статус:** выполняется в RC batch

Сохранение/отпускание и сближение/избегание дают различимые состояния без выбора класса.

### IMP-V4-009. Полный offline shell
**P1**
**Статус:** реализовано

Каждый актуальный JavaScript-модуль, необходимый браузерному берегу, присутствует в service-worker cache. Cache version поднят до v4.

### IMP-RC-009. Корректное ранжирование осей траектории
**P0 — RC blocker**
**Статус:** реализовано

`Trajectory.build()` сравнивает фактические значения осей DNA по именам осей и закреплён детерминированными сценариями трёх контрастных путей.

### IMP-RC-010. Траектория из активного игрового контекста
**P0 — RC blocker**
**Статус:** реализовано

Release layer строит траекторию из конкретного активного `game` через `Trajectory.build(game)`, сохраняя глобальный save лишь как память результата. Это исключает загрязнение между параллельными жизненными контекстами.

## PHASE 10 — Release Candidate

### IMP-RC-001. Unified release systems layer
**P0**
**Статус:** выполняется

Единый bounded state для причинности, мира, отношений, тела, финалов и следующей жизни.

### IMP-RC-002. Deterministic control scenarios
**P0**
**Статус:** выполняется

RC должен проверять реальные игровые сигналы, а не искусственно заполненные счётчики.

### IMP-RC-003. Save budget + migration envelope
**P0**
**Статус:** выполняется

Состояние ограничено по размеру и имеет проверяемую миграцию старых сейвов.

### IMP-RC-004. RC gate probe
**P0**
**Статус:** выполняется

Один acceptance probe проверяет количественные и качественные условия готовности.

### IMP-RC-005. Canonical trajectory bridge
**P1**
**Статус:** реализовано

Release layer использует `Trajectory.profile()` как канонический источник пути, а для активного игрового контекста строит профиль через `Trajectory.build(game)`.

### IMP-RC-006. Canonical life behavior bridge
**P1**
**Статус:** реализовано

Release layer использует реальную схему `Life.profile().behavior`.

### IMP-RC-007. RC version identity
**P0**
**Статус:** реализовано

Версия игры, APK и publish-документа синхронизированы на RC1.

### IMP-RC-008. Real trajectory control scenarios
**P0**
**Статус:** реализовано

RC использует три контрастных игровых портрета и требует три разные канонические траектории.

### IMP-RC-009. Correct trajectory axis ranking
**P0**
**Статус:** реализовано

Исправлено ранжирование DNA-осей и закреплено отдельной проверкой. Ошибка могла стирать различия между жизненными путями.

### IMP-RC-010. Active-game trajectory context
**P0**
**Статус:** реализовано

ReleaseSystems строит траекторию из конкретного активного `game`, чтобы разные жизненные контексты не наследовали последний глобальный профиль из кеша.

## Definition of Done — Release Candidate

- минимум 3 акта;
- минимум 3 различимые жизненные траектории;
- минимум 3 финальных состояния мира;
- минимум 8 исторических мест;
- минимум 6 повторяющихся ключевых существ;
- минимум 5 длинных причинных цепочек;
- минимум 10 редких личных событий;
- offline core;
- стабильный Android APK и save;
- migration старых сейвов;
- полный CI green;
- 0 critical/blocker;
- без обязательной сети, монетизации, рекламы, streak/daily reward или FOMO-механик.
